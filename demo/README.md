# Demo corpus (synthetic)

Everything in this folder is **fictional** and generated by
[`tools/Adelaide.SampleGen`](../tools/Adelaide.SampleGen/Program.cs):

- **People.** Names use the conventional German placeholders (Mustermann, Musterfrau, Beispiel, Testfall, Probe).
  Each insurance number (KVNR) is a low-entropy synthetic value with a valid check digit, such as `M111111119`.
  `Z000000005` and `T000000002` are the synthetic values the unit tests already use.
- **Organisations.** Every practice, hospital, insurer and supplier is labelled *(fiktiv)*, and all addresses are
  "Musterstraße 1, 12345 Musterstadt" style.
- **Layout.** The PDFs are simple letters with a "SYNTHETISCHES MUSTERDOKUMENT" banner on every page. They do not
  reproduce official KBV or insurer form designs.

| File | Contents |
|---|---|
| `samples/*.pdf` | 9 sample documents, byte-deterministic |
| `fixtures.json` | for each sample (keyed by SHA-256): the per-page transcript, legibility, and the fields the production extractor would be expected to return. `units` holds per-page-range fields for the split scenario. |
| `patients.json` | the synthetic patient directory (7 records, including a same-name/same-DOB pair and an active/inactive pair) |

Regenerate with `dotnet run --project tools/Adelaide.SampleGen`. The output is deterministic, so a clean checkout
reproduces byte-identical files.

## What demo mode does and does not do

Demo mode (`ADELAIDE_DEMO_MODE=1`, started by [`scripts/run-demo.sh`](../scripts/run-demo.sh)) runs the **real**
`Adelaide.Web` host and Angular UI. It replaces four adapters:

| Production adapter | Demo stand-in | Effect |
|---|---|---|
| GPT-4o vision transcriber | `DemoTranscriber` | Looks the uploaded PDF up by SHA-256 and replays the recorded page text. Unknown PDFs transcribe to nothing and go to review. |
| Azure OpenAI extractor | `DemoExtractor` | Replays the recorded fields for that transcript. |
| SharePoint *Patients* list | `DemoPatientDirectory` | Same matching strategy (`PatientMatching.MatchAsync`) over `patients.json`. |
| SharePoint filer + Document Intelligence rendition | `LocalFolderFiler` + `NoTextLayer` | "Files" into `.adelaide-demo/filed/<site>/<library>/` with a JSON metadata sidecar. |

**Not simulated:** OCR or LLM quality, barcode decoding of real scans, Graph throttling, SharePoint column validation,
and Entra sign-in. Demo mode uses the Development-only local identity, so every request is a Reviewer and Admin.
Ledger events keep their production actor labels (`vision`, `graph`, `sharepoint`) because the host code is unchanged.
The `Extracted` event records `model = demo-fixture`.

**Safety:** the host refuses to start in demo mode if any production setting is present (SQL, Key Vault, App
Insights, staging share, Entra secrets, AI endpoints). It also blocks every outbound HTTP connection and token request.

## Walkthrough

1. `scripts/run-demo.sh --reset`, then open <http://localhost:5080>.
2. Upload `01`, `02` and `04`–`09`. Expect two **Abgelegt** (filed) and the rest under **Prüfung** (review), each
   with its reason.
3. Upload `03` (the fax copy of `02`). It goes to review as a possible duplicate, and **Vergleichen** opens the
   side-by-side compare.
4. Upload `02` again. It is held under **Duplikat?** before any processing.
5. Open `05`. Two candidate patients are offered, so pick one and submit (**Prüfen und ablegen**). The document is
   written under `.adelaide-demo/filed/`, and its history shows `NeedsReview → Filing → Reviewed → Filed`.
6. Open `09` and split it into pages 1 and 2. The prescription half auto-files; the lab-report half goes to review.
7. `GET /api/audit/verify` recomputes the whole hash chain.
